Wallboard and Yodeck configuration

The wallboard is a static React view backed by the deployed status.json payload. URL options control the incident time window and how often the browser checks that deployed payload. They do not change vendor collection cadence and they do not require Yodeck scripting.

Recommended 46 inch TV URL

https://dmo18.github.io/sst/?view=wallboard&alerts=24h&refresh=3m

The three-minute browser check is the default, so refresh=3m is optional. Keeping it explicit in the signage URL makes the intended configuration easy to audit.

Incident window

Use alerts= to include active vendor incidents whose latest vendor update falls inside a rolling window.

Examplesalerts=90m, alerts=24h, alerts=2d
Minimum1 minute
Maximum30 days
Invalid valueAll active incidents remain eligible.

Browser refresh interval

Use refresh= to control how often wallboard mode fetches and validates the deployed status.json payload while the page is visible.

Examplesrefresh=30s, refresh=1m, refresh=3m, refresh=5m, refresh=1h
Minimum15 seconds
Maximum1 hour
Default3 minutes
Invalid valueFalls back to the 3-minute default.

Browser in the wallboard telemetry is the age of the most recent successful browser payload check. The refresh URL option controls when the next check is attempted.

Compact TV presentation

  • The 458 by 291 layout is the primary Yodeck tile contract.
  • Active provider icons and provider names share the top scrolling rail.
  • Payload and browser-check freshness remain fixed on the right side of that rail.
  • Incident rows retain provider icon, provider name, update age, title, and complete vendor detail text.
  • The provider rail scrolls horizontally only when needed.
  • The incident list scrolls vertically only when needed.
  • The full header and KPI overlay can remain minimized for unattended signage.

Yodeck settings

  • Use the wallboard URL directly as a Web Page.
  • Keep Chromium enabled for modern page support.
  • Use 100 percent zoom.
  • Do not add Yodeck scripting or browser-side vendor requests.
  • The app already performs its own payload checks. Yodeck full-page refresh is a separate setting and is not required for the refresh URL option.
  • After a new production deployment, reload or republish the Yodeck screen if it has not picked up the new built assets.

What the freshness values mean

PayloadAge of the deployed payload generated by the collection pipeline.
BrowserAge since this browser last fetched and successfully validated the deployed payload.
refreshThe configured wallboard interval between browser payload checks. It does not force GitHub Actions or vendor collection to run.
